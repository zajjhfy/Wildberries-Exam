# Wildberries Exam

Командный учебный проект. Рабочие ветки создаём от актуального `dev`, PR направляем в `dev`.

## Запуск

- Xcode с поддержкой Swift 6.3 (проверка выполняется в Xcode 26.6).
- Deployment target приложения и пакетов — iOS 18.0.
- Открыть `WildberriesExam.xcodeproj` и разрешить запуск плагина `OpenAPIGenerator` от Apple.
- Создать `WildberriesExam/Config/Secrets.xcconfig` по образцу `Secrets.example.xcconfig`:

```xcconfig
API_KEY = YOUR_API_KEY
```

Вместо `YOUR_API_KEY` указать действующий ключ без кавычек и без префикса `Bearer`.
`App.xcconfig` подключает локальный файл для Debug и Release. После изменения ключа нужно пересобрать приложение.
`Secrets.xcconfig` исключён из Git и из ресурсов приложения. В собранный `Info.plist` попадает значение ключа: это учебная настройка, а не защищённое хранилище секрета в готовом приложении.

Без ключа проект можно собирать и запускать unit-тесты. Создание настоящего API-клиента с пустым ключом возвращает `NetworkError.missingAPIKey`; тестовые данные не подставляются автоматически.

## Ответственность пакетов

- `NetworkPackage`: OpenAPI-клиент, авторизация, ошибки HTTP/сети и API каталога.
- `BusinessLogic`: модели для экранов, сервис каталога, `CatalogViewModel` и явный `PreviewCatalogService`.
- `DesignSystem`: оформление и UI-компоненты. Пакеты сети и бизнес-логики от него не зависят.
- `WildberriesExam/Config/AppDependencies.swift`: сборка настоящих зависимостей приложения.

OpenAPI-код создаётся плагином из `Packages/NetworkPackage/Sources/NetworkPackage/openapi.json`.
Генерируемые файлы не редактируем вручную и не добавляем в Git. Они публичны для межпакетного маппинга; экраны получают модели `BusinessLogic`, а не DTO.

## Подключение каталога к экранам

В точке сборки приложения создать `AppDependencies` один раз и передать сервис в ViewModel. Ошибку конфигурации обработать на уровне приложения:

```swift
let dependencies = try AppDependencies()
let catalog = CatalogViewModel(service: dependencies.catalogService)
```

Для независимой работы над UI:

```swift
let catalog = CatalogViewModel(service: PreviewCatalogService())
```

ViewModel изолирована `MainActor` и поддерживает Observation. Владелец экрана сохраняет её экземпляр, вызывает `await catalog.load()` из `.task` и передаёт действия в следующие методы:

| Метод | Поведение |
|---|---|
| `load()` | Загружает категории и первую страницу параллельно; не повторяет успешную загрузку при возврате на экран |
| `refresh()` | Обновляет категории и первую страницу текущей категории |
| `selectCategory(_:)` | Меняет категорию и сбрасывает страницы; `nil` означает все товары |
| `loadNextPage()` | Загружает следующую страницу, защищает от одновременных повторов; также используется для повтора после ошибки |

- `state`: `.idle`, `.loading`, `.loaded`, `.failed(message)`.
- `categories`, `products`, `selectedCategoryID`: данные экрана.
- `isEmpty`: успешная загрузка без товаров.
- `hasNextPage`, `isLoadingNextPage`, `nextPageError`: состояние подгрузки.
- При ошибке подгрузки уже загруженные товары сохраняются. Номер страницы увеличивается только после успеха.
- Поздние ответы старой категории не заменяют текущие данные. Отмена задачи не отображается как сетевая ошибка.
- Некорректная ссылка на изображение преобразуется в `nil`, чтобы UI мог показать заглушку. Вес и рейтинг остаются дробными, цена — `Int`, как в API и карточке `DSProductCard`.

### Стыковка с дизайн-системой

- В `DSCategoryCard` передаются `category.name` и `category.imageURL?.absoluteString ?? ""`.
- Для карточки товара: `product.name`, `product.price`, `product.rating`, `product.reviewCount`, `product.isFavorite` и `product.imageURL?.absoluteString ?? ""`. Форматирование веса в `weightText` выполняется на уровне представления.
- `quantity/count` — состояние корзины, а не локальное состояние кнопки. На следующем этапе сервис/ViewModel корзины будет обрабатывать `onIncrement`/`onDecrement` и публиковать новое количество. Внутри DS-кнопки повторно менять его не нужно.
- `DSAsyncImage` уже загружает и кэширует изображения. Второй загрузчик в `NetworkPackage` не добавляем; DTO и модели содержат только ссылку.
- `isFavorite` пока загружается с сервера; действия изменения избранного и корзины в этот PR не входят. До их подключения нельзя считать кнопки полностью рабочими.

Сами экраны, навигация и загрузчик изображений в этот этап не входят.

## Проверки

Unit-тесты находятся в `NetworkPackageTests` и `BusinessLogicTests`. В Xcode открыть `Package.swift` соответствующего пакета отдельно, выбрать схему пакета и iOS Simulator, затем выполнить Test. Автоматические схемы пакетов внутри проекта приложения не включают test action.
Тесты используют подменный транспорт и управляемый сервис: настоящий ключ и доступ к бэкенду не требуются.

Покрываются авторизация и параметры запроса, декодирование, HTTP-ошибки с нестандартным телом, отмена, маппинг, пагинация, повтор после ошибки и ответы запросов, пришедшие в обратном порядке.

`LiveCatalogTests` выполняется только при явно заданной переменной окружения теста `LIVE_CATALOG_API_KEY`. Это отдельная проверка чтения категорий и товаров на учебном сервере; по умолчанию она пропускается. Не сохранять ключ в общей схеме, test plan или репозитории.

Для полной реализации задания ещё нужно согласовать источник геолокации/адресных подсказок и подгрузку истории: текущий `GET /orders` не содержит параметров пагинации. Поиск товаров на сервере также не описан в текущей спецификации.
